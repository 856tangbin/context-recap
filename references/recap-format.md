# 摘要模板与示例

## 完整模板

```markdown
# 问题背景摘要

> 最后更新：2026-10-16 14:20 · 状态：进行中

## 为什么问这个
<一到两句现实起因>

## 目标
<要达成什么；怎样算完成>

## 现在的进度
- 已完成：
- 未完成 / 受阻：

## 下一步
- 
```

## 正例

```markdown
# 问题背景摘要

> 最后更新：2026-10-16 14:20 · 状态：进行中

## 为什么问这个
同时挂了三个 Agent 帮我排查线上问题，每个都要半小时以上才回。
过一阵子我自己忘了当初为什么要问，只能重新翻聊天记录。

## 目标
做一个 DSH 侧边栏/技能，让每次回答结束时自动显示「这问题是为什么、做到哪了」。

## 现在的进度
- 已完成：确认 `sidebar_open` 工具可用，侧边栏插件 `dsh-better-sidebar@0.26.0` 已装；
  摘要文件路径定为工作区根的 `.context-recap.md`。
- 未完成：还没验证 `.md` 预览是否自动刷新。

## 下一步
- 写 `install.ps1`，把 skill 装到 `~/.dsh/skills/context-recap/`。
- 若自动刷新不可用，退化为每轮由 `sidebar_open` 重新聚焦标签页。
```

为什么合格：起因是现实痛点而不是问题字面；目标可验证；进度带具体组件名和版本;下一步是动作。

## 反例

```markdown
# 摘要

## 背景
用户问了一个关于插件的问题。

## 目标
帮用户解决问题。

## 进度
已经做了很多分析，进展顺利。
```

为什么不合格：复述了问题字面而没有说「为什么」；「进展顺利」不可验证；
没有路径 / 版本 / 结论，几小时后的自己读了等于没读。

## 长度参考

- 正常：12–18 行。
- 上限：20 行。超了就是写成了报告，删掉过程，只留结论。
